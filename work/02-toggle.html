01 Context

왜 이 프로젝트를 했는가

Toggle은 Gmail, Slack, Notion 등 분산된 업무 툴을 하나의 플랫폼에서 통합 관리할 수 있는 B2B SaaS 서비스입니다. 시드 투자 유치 후 서비스 성장 단계에서 핵심 지표인 홈 화면 체류시간이 평균 3초 미만으로 낮게 나타나는 문제가 있었습니다.

기존 홈 화면은 통합 검색 기능만 제공하는 구조였습니다. 유저가 로그인 후 처음 접속하는 페이지임에도 불구하고, 업무 흐름을 파악하거나 프로젝트 단위로 정보를 확인하려면 반드시 다른 화면으로 이탈해야 하는 구조였습니다.

외부 디자이너 8인 스프린트 구조로 진행된 프로젝트로, 개인별 독립 솔루션 제출 후 상호 피드백하는 방식으로 운영되었습니다.

02 Problem

문제의 크기

홈 화면이 허브 역할을 하지 못하면서 평균 체류시간 3초 미만이라는 수치가 나타났습니다. 이는 단순한 UI 문제가 아니었습니다.

홈 화면에서 사용자의 행동이 검색에만 제한되면, 통합 솔루션에 대한 필요성을 느끼지 못해 재접속률까지 낮아지고 서비스 리텐션이 떨어집니다.
단순 체류시간 문제가 아니라 서비스 핵심 가치 전달 실패였습니다.

  • 문제 1
    낮은 체류시간 — 홈 화면 평균 3초 미만. 통합 검색 외 활용 가능한 인터페이스 부재
  • 문제 2
    주요 기능 화면 이탈 — 업무 흐름 파악을 위해 각 기능 페이지로 이동해야 하는 구조. 홈이 허브 역할을 하지 못함
  • 문제 3
    서비스 가치 미전달 — 연동된 비즈니스 서비스를 활용하기 어려운 구성. '효율적인 업무 관리'라는 핵심 가치를 체감할 수 없음
03 Decision

무엇을 하고, 무엇을 하지 않았는가

핵심 판단은 통합 검색을 제거하지 않되, 홈 화면의 역할을 '검색 진입점'에서 '업무 허브'로 재정의하는 것이었습니다. 체류시간 6초 이상을 Target Metric으로 설정했습니다.

비즈니스 목표인 서비스 리텐션 개선을 솔루션 설계의 기준으로 연결했습니다. 단순히 화면을 개선하는 것이 아닌, 사용자가 홈 화면에서 오래 머물 이유를 만드는 것이 핵심이었습니다.

  • 한 것
    프로젝트 단위 업무 데이터 분류와 칸반보드 기반 홈 화면으로 재설계. 연동된 SaaS 데이터가 홈 진입 즉시 보이는 구조로 전환
  • 하지 않은 것
    각 기능 페이지의 완전한 재설계. 홈이 모든 기능을 보여주려는 욕심을 버리고 '업무 흐름 파악'에만 집중
  • 기준
    사용자의 익숙한 칸반 인터랙션 패턴을 그대로 활용해 학습 비용 최소화. 드래그앤드롭과 업무 추가하기 버튼의 이중 진입점 설계
04 Design

솔루션 — 업무 허브로서의 홈

프로젝트 단위로 재구조화된 홈 화면은 사용자가 이탈 없이 업무 현황을 파악하고 처리할 수 있는 허브로 작동합니다.

To-be — 칸반 기반 프로젝트 허브 홈 화면 이미지 준비 중

D-Day / 진행 상태

마감일과 진척도 직접 노출

의사결정에 필요한 핵심 정보를 카드에 직접 표시하여 한눈에 확인 가능

프로젝트가 많아질수록 홈 화면의 정보 밀도가 높아지는 문제를 대비해, 사용자가 원하는 프로젝트를 탐색 없이 즉시 찾을 수 있도록 정렬과 필터 기준을 각각 분리하여 설계했습니다.

정렬 / 필터 구성안 이미지 준비 중

최초 로그인 시 앱 연동을 완료하지 않으면 서비스 활용이 어렵기 때문에, 온보딩 팝업을 통해 연동 과정과 기능 학습을 자연스럽게 유도하는 플로우도 함께 설계했습니다.

온보딩 팝업 — 최초 로그인 시 연동 및 기능 학습 유도 이미지 준비 중

06 Review

회고

What Changed

홈 화면의 역할 재정의

통합 검색 중심의 단일 기능 화면을 프로젝트 단위 칸반보드로 재구조화하여 홈 화면이 업무 허브로 작동하도록 설계

비즈니스 목표를 설계 기준으로

체류시간 3초 미만이라는 데이터를 출발점으로, MAU 상승과 서비스 리텐션이라는 비즈니스 목표를 솔루션 설계 기준으로 연결

토글캠퍼스 팀 피드백

정보 구조 재설계 방향이 명확하게 드러나며, 시각적 위계와 인터랙션 플로우가 설계 의도와 잘 맞았다는 피드백을 받음

What I'd Do Differently

정보 분류 자동화 설계 필요

프로젝트 카드에 정보를 직접 분류하는 방식은 또 다른 업무를 만드는 구조로, AI 기반 자동 분류 시스템을 통해 사용자 개입 없이 정보가 정리되는 방향으로 설계했다면 서비스 가치가 더 높아졌을 것

실제 검증 데이터 확보 부재

체류시간 6초 이상이라는 Target Metric은 가설 수치. 프로토타입 테스트를 통한 실제 사용 데이터를 확보했다면 솔루션의 설득력이 더 높아졌을 것
